# 08. Definição de pronto

Uma entrega só está pronta quando todos os itens aplicáveis forem atendidos.

## Estrutura

- segue os contratos;
- mantém nomes de arquivos e rotas consistentes;
- não inclui arquivos temporários;
- não inclui dependências externas não aprovadas.

## Interface

- funciona em telas pequenas e grandes;
- usa a paleta definida;
- carrega Bootstrap localmente;
- aplica estilos próprios depois do Bootstrap;
- não apresenta quebra visual evidente.

## Qualidade

- HTML semântico;
- links válidos;
- imagens otimizadas;
- sem erros no console;
- sem conteúdo inventado;
- sem segredos;
- acessibilidade básica validada;
- metadados principais preenchidos.

## Publicação

- GitHub Pages configurado;
- workflow de validação, build e deploy concluído sem erros;
- artefato contém somente arquivos públicos;
- manual e modelo de publicação não são publicados;
- índice JSON, páginas individuais e sitemap são consistentes;
- domínio confirmado antes de criar `CNAME`;
- HTTPS ativo;
- rotas e recursos validados no ambiente publicado.

## Registro

A mudança deve indicar:

- o que foi alterado;
- quais contratos foram atendidos;
- o que continua pendente;
- quais dados ainda exigem confirmação.
